No built-in Lottie player ships with the runtime; `<lottie>` is a MODULE element, and the Core/Lottie web facet (the vendored lottie-web light player, MIT, pinned) fills the tag through the module component loader whenever the module is registered.

**Known limits on the web**

- With Core/Lottie registered the facet consumes src (a Lottie .json URL, absolute or site-relative), loop, speed, autoplay, a11yLabel and on:finish; loading and failure render labelled states inside the element's own box, and prefers-reduced-motion pins the static first frame.
- The module facet renders via SVG only and plays plain Lottie JSON: dotLottie (.lottie) archives, bundled-name lookup, and expression-driven animations are not supported on this surface.
- Without the module (excluded builds, sliced embeds), src, loop, speed, and autoplay are not consumed.

**Fallback.** Mounts the honest dsx-unsupported placeholder whenever the Core/Lottie module is absent - a labelled marker carrying the `<lottie>` name and the dsx-unsupported class; never blank, never a fake lookalike of the native surface.

**Implementation notes.** Portable sources: HTTP(S) plain Lottie JSON. Native bundled JSON names use app bundle/APK assets; web also supports document-relative JSON URLs. Archives are outside the portable contract. Positive finite decimal speed representable by the single-precision native player or 1; autoplay changes pause/resume a mounted source. Ready label is trimmed aria-label or Lottie animation; loading/failed labels report availability.

Declared platforms: `ios`, `android`.
