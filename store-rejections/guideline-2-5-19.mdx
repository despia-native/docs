Apple App Review guideline 2.5.19 asks an app to declare the native features it ships. Despia builds your app with the native features and SDKs it needs, so the review sees what your app uses.

## Detection

Every native feature has its own URL scheme named after its API, such as `revenuecat://`, `onesignal://`, `lighthaptic://` or `bluetooth://`, and the `despia-native` npm package calls the same features. Despia scans your web app in the background for those calls and for SDK usage, and shows the result under **Builder > Native features**. A feature your code uses is included in the next build. When your app uses a feature that isn't imported yet, the dashboard suggests **Import all**. Features used through standard browser APIs, such as camera, microphone and location, are detected too. Most apps need nothing here.

## Import at deploy

When you deploy and your app uses a native feature it hasn't imported yet, Despia tells you which one and offers to import it. Choose **Import** and the feature is included in that build.

## Enable a feature

1. Open your app in the dashboard and go to **Builder > Native features**.
2. Find the feature and switch it to **Enable**.
3. Publish. If the feature is new to this app, a popup asks for a new version. Pick the next minor, the next major, or a custom number.

## Overrides

| Setting | Result |
| --- | --- |
| Auto | Included when your web code uses it. |
| Force on | Always included. |
| Force off | Never included. |

Use **Force on** for features your web code loads at runtime in a way the scan cannot see.

## Versions

A published version keeps the feature set it was built with. Adding a feature needs a new version, which is why the popup appears on Publish. Removing a feature needs no new version.
